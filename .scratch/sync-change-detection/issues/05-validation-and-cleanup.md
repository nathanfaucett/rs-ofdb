### Measured improvement and retained limits

- The selected SQL fixture passes: two direct summaries, zero table/row-ID scans, zero snapshot exports, zero separate history inventory calls, zero digest reloads, one native change frame (both peers combined). Original ticket01 baseline: 49 snapshot exports / 26 inventory calls / 48 digest reloads. These are public-call counters, not a count of all private reconstructions.
- The selected KV fixture passes with 101 keys per peer: four total inventory entries across directional comparisons, zero snapshots and fewer than 100 physical record reads per peer; replay sends no data.
- Retention is one 128-commit ring per signal, at most 128 physical invalidations / 16 KiB of identity bytes per commit; oversized commits become All. A token can combine retained commits. These are notification-retention bounds, not bounds on all transaction/session memory. Select before reads; acknowledge only successful selected work; failures/cancellation retry without advancing; later commits and other peers remain pending.
- New/cloned/reconnected peers, restart, gaps/overflow and unknown writes compare broadly. SQL catalog/dependency invalidation remains broad; table invalidation permits table scans. KV re-reads latest generations and enumerates full selected-document history, with whole-store inventory on broad fallback. Single-document/frame budgets can reject oversized work rather than chunking it.
- Local subscriptions cannot detect remote-only commits, external/raw writes or independent wrappers' writes. Caller-driven authorized remote wakeups/receive delivery or explicit two-sided reconciliation are required, even with empty local selection. Per-peer unmerged subscriptions must be recreated on reconnect. SQL memory supports notifications; KV memory uses explicit broad sessions. No durable replay, persistent peer cursor, globally atomic/frozen session or automatic bidirectional realtime promise was added.
