## Consumer blocker and contract

Read original of docs/public-persistence.md concrete bootstrap handoff125–155, offline-first-nodes spec and latest03 marker3 handoffs. Scalar historical-value validation cannot correlate actual complete row identity/bindings or prospective local related rows/conflicts. Actor/action/provenance and bootstrap admission remain of-owned; no ledger, original-mutator claims or domain traits belong in storage.

Add smallest public synchronous callback with owner-materialized read-only complete-row evidence, candidate keys and incoming/outgoing direction. Selected table column names, logical UUID, actual Row, tombstone and all native concurrent values are observed from the same transaction; selected related rows in the current apply batch must already be merged before validation. No independent Database read or async/network wait is supplied under write transaction. Outgoing evidence comes from actual source read/export, not scalar reconstruction. Historical-value checks remain mandatory and independent. No domain trust is granted to pending/incomplete rows by storing them.

## Acceptance

- Public scoped memory/native-stage facades expose only public data, borrowed synchronous validation; existing signatures/features/no_std remain supported.
- Incoming snapshot/delta/fallback/recovery batches use the shared post-merge/pre-commit validator, fail atomically; earlier valid progress survives. Native reopen preserves conflicts/tombstones and denied data stays absent.
- Correlation with another row in same atomic snapshot; current local mutation after preflight is observed by actual incoming transaction; losing conflict values observable; pending missing related evidence can persist when consumer chooses, without owner granting trust.
- Outgoing actual complete-row/source read evidence and related rows observed together; contaminated correlation rejects before disclosure. Historical scalar checks unchanged.
- Focused TDD/repeats/qualification, exact failures/limits documented. No CRAP/hack/sweeps. Isolated owner target verified then cleaned. Commit for independent review; do not resolve before review.
